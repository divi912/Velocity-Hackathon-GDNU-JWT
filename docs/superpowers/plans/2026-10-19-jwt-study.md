# JWT, decoded Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task when native execution is selected. Steps use checkbox syntax for tracking.

**Goal:** Build a local, polished React/Vite JWT lesson with scroll-controlled server graphics, real signing/verification experiments, simple wording, mono body text, and a final pros-and-cons section.

**Architecture:** A single React page contains an editorial opening, seven narrative chapters, a token laboratory, and a closing comparison. GSAP controls the SVG diagrams from scroll position; Framer Motion handles interactive changes. Framework-independent helpers use Web Crypto for real HS256 operations in a clearly marked local simulation.

**Tech Stack:** React, Vite, TypeScript, Tailwind CSS, GSAP ScrollTrigger, Framer Motion, Lucide React, local font packages, Node's built-in test runner.

**Spec:** `../specs/2026-10-19-jwt-study-design.md`

## Global Constraints

- React + Vite, TypeScript modules, Tailwind CSS utilities and shared theme tokens.
- No deployment, login, database, or account system is required.
- Use JetBrains Mono for body text, explanations, controls, labels, and code; keep Playfair Display for the oversized editorial titles.
- Define necessary technical terms in place. Avoid academic vocabulary and unexplained security jargon.
- Black and white, sharp corners, strong rules, subtle paper/grid textures, and generous whitespace.
- Reduced-motion mode presents static complete diagrams and direct state changes, and also supports an explicit motion toggle.
- After the laboratory, include the final learning section, “Where JWT helps. Where it gets tricky.”

## Review Focus

- Unicode text must round-trip through Base64url; test in Task 1.
- A valid signature must remain distinguishable from expired or wrong-audience claims; test in Task 1 and exercise in Task 3.
- Fast edits and reset during async verification must not show an older result; exercise in Task 3.
- Mobile widths and reduced motion must keep all diagrams and chapter text readable; inspect in Task 2.
- Malformed JSON or a malformed token must give a useful error and allow recovery; test in Task 1 and exercise in Task 3.

## File structure

- `package.json`, `index.html`, `vite.config.ts`: local runtime, build, and test commands.
- `src/main.tsx`, `src/App.tsx`: entry point, motion preference, page composition.
- `src/index.css`: shared tokens, fonts, responsive layout, diagram and lab styling.
- `src/lib/jwt.ts`, `src/lib/jwt.test.ts`: encoding, parsing, HS256 signing, signature checks, claim checks, permission checks, and behavior tests.
- `src/content/chapters.ts`: seven lessons and their plain-language copy.
- `src/components/Navigation.tsx`: chapter links, progress, and motion toggle.
- `src/components/Story.tsx`: hero, lessons, closing pros/cons, and standards links.
- `src/components/Diagrams.tsx`: SVG client/server, token anatomy, encoding, signing, verification, and expiry graphics.

- `README.md`: local commands, lesson scope, and public demo key explanation.

## Task 1: Working token model and project setup

**Interfaces:** Export `encodeText(text): string`, `decodeText(encoded): string`, `parseToken(token): {header, payload, segments}`, `signToken(payload, options?): Promise<string>`, `verifyToken(token, options?): Promise<{checks, accepted, header, payload, signingInput, expectedSignature}>`, and `replacePayload(token, payload): string`. Verification options include `now`, `audience`, `issuer`, `endpoint`, and `secret`. Each check has `id`, `label`, `status`, and `detail`; status is `pass`, `fail`, or `skip`.

- [ ] Run `node --test src/lib/jwt.test.ts` and confirm failure because the helper module is absent.
- [ ] Create the runtime files and JWT helpers. Use strict Base64url parsing, UTF-8 text encoding, Web Crypto `subtle.sign`/`subtle.verify`, an HS256 allowlist, an application-defined claim policy, and a separate endpoint permission check.
